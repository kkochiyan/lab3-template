# API Gateway

Из корня проекта запусти все сервисы через зависимости Gateway:

```bash
docker compose up -d --build gateway-service
curl -f http://localhost:8080/manage/health
```

Публичные маршруты варианта 2 доступны под `/api/v1`. Gateway связывается с тремя
сервисами по HTTP. Для локального запуска по умолчанию используются Reservation
на `localhost:8070`, Payment на `localhost:8060` и Loyalty на `localhost:8050`.

При создании брони Gateway читает скидку до регистрации новой брони. Платёж
выражен целым числом: дробная часть после скидки округляется до ближайшей
целой денежной единицы, половины округляются вверх. Публичный ответ отдаёт
скидку числом, как в примере OpenAPI и проверках Postman.

На чтение у каждого из трёх сервисов свой Circuit Breaker. После трёх
неудачных запросов Gateway на две секунды перестаёт отправлять новые запросы
к этому сервису. Затем пропускает один пробный запрос. Обычные ошибки вроде
404 не открывают circuit. Если отсутствуют сведения об оплате или лояльности,
Gateway отдаёт `{}` в необязательной части ответа. Недоступность основного
сервиса возвращает 503; некорректный ответ основного сервиса — 502.

Отмена проверяет владельца, отменяет платёж и бронь, затем уведомляет Loyalty.
Если Loyalty недоступен, Gateway возвращает 204 и повторяет только последний
шаг каждые 10 секунд. Задачи в памяти дедуплицируются по пользователю и брони;
перезапуск Gateway сбрасывает очередь. Операция в Loyalty идемпотентна.

При ошибке Loyalty во время создания Gateway отменяет подтверждённую бронь
и оплату. POST не повторяется автоматически: при обрыве ответа результат
создания может быть неизвестен. Гарантированное восстановление записи
после таких сбоев требует идемпотентности создания и хранения состояния.

Локальные тесты Gateway из его каталога:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Проверка отказоустойчивости варианта 2 из корня проекта на чистой тестовой
базе (требуется установленный Newman):

```bash
./scripts/test-script.sh v2 loyalty-service 8050
```
